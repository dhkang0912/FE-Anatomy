# 코어 자바스크립트
# 3. this
- 대부분의 객체 지향 언어에서는 `this`는 클래스로 생성한 인스턴스 객체를 의미함  
  => But, 자바스크립트는 어디서든 `this`를 사용할 수 있고 상황에 따라 `this`의 가르키는 대상이 달라짐
- `함수와 객체(메서드)`의 구분이 느슨한 자바스크립트에서 `this`는 실질적으로 이 둘을 구분하는 거의 유일한 기능

## 3-1. 상황에 따라 달라지는 this
- `this`는 실행 컨텍스트가 생성될 때 함께 결정됨
  - 실행 컨텍스트는 함수를 호출할 때 생성됨 => 결국 `this`는 함수를 호출할 때 결정됨

### (1) 전역 공간에서의 this
#### 1. 전역 공간에서 `this` : 전역 객체
  - 개념상 전역 컨텍스트를 생성하는 주체 = `전역 객체`
  - 전역 객체는 런타임 환경에 따라 다른 이름, 정보를 가짐
    - 브라우저 전역객체 : window
    - Node.js 전역객체 : global

    ![Alt text](<images/환경에 따른 전역 객체.png>)

<br>

#### 2. 전역 공간에서 발생하는 특이한 성질
- 전역 변수 : `변수`이자 `전역 객체의 프로퍼티`
- 예시 : 전역변수와 전역객체
    ![Alt text](<images/전역변수와 전역객체.png>)
    - 전역 공간 선언한 `변수 a`
    - `window.a`, `this.a` 모두 동일하게 `1`을 출력함

    <br>

    - `var` 연산자로 변수를 선언하더라도 실제 자바스크립트 엔진은 `특정 객체의 프로퍼티`로 인식

<br>

- **자바스크립트의 모든 변수는 실행 컨텍스트의 `LexicalEnvironment` 객체의 프로퍼티로 동작**
  - 변수 호출 시 `L.E`를 조회하여 일치하는 프로퍼티가 있을 경우 그 값을 반환
  - 전역 컨텍스트의 경우 `L.E`가 전역객체를 그대로 참조
  - `전역변수를 선언`하면 자바스크립트 엔진이 `전역객체의 프로퍼티로 할당`
    - window, this로 전역객체의 변수를 접근 가능
    - `변수 식별자`로 접근을 시도하는 경우 `스코프 체인`에서 도달하는 값을 찾아 반환 => `window.`이 생략된 것으로 이해해도 됨

<br>

- **전역 변수 선언과 삭제**
  - 전역 변수 선언
    - `var` 변수 선언 = `window` 프로퍼티 할당
  - 전역 변수 삭제
    - `var` 변수 선언 != `window` 프로퍼티 할당
    - **전역변수로 할당한 후 삭제**하는 경우 **삭제되지 않지만** **전역객체의 프로퍼티로 할당한 경우 삭제**됨
        ```js
        var a = 1;
        delete window.a; // false
        console.log(a, window.a, this.a); // 1 1 1

        var b = 2;
        delete b; // false
        console.log(b, window.b, this.b); // 2 2 2

        window.c = 3;
        delete window.c; // true
        console.log(c, window.c, this.c); // Uncaught ReferenceError: c is not defined

        window.d4;
        delete d; // true
        console.log(d, window.d, this.d); // Uncaught ReferenceError: d is not defined

        ```
      - 전역 객체 선언 시 의도치 않게 삭제하는 것을 방지하는 `방어 전략`

### (2) 메서드로서 호출할 때 그 메서드 내부에서의 this
#### 1. 함수 vs 메서드
- **함수를 실행시키는 두가지 방법 : 함수로서 호출, 메서드로서 호출**
    - 함수와 메서드는 미리 정의한 동작을 수행하는 코드 뭉치
    - **유일한 차이점** : **독립성**
      - 함수 : 그 자체로 독립적인 기능을 수행
      - 메서드 : 자신을 호출한 대상 객체에 관한 동작을 수행
    - 자바스크립트는 `상황별`로 `this` 키워드에 다른 값을 부여하면서 이를 구현

<br>

- **메서드**
  - 객체의 프로퍼티에 할당된 함수
  - **객체의 메서드로서 호출할 경우에만 메서드로 동작되고 그렇지 않으면 함수로 동작**
    - 예시 : 함수로서 호출, 메서드로서 호출
    ![Alt text](<images/함수로서 호출, 메서드로서 호출.png>)
      - `func` 변수에 익명함수를 할당한 후 `func`을 실행하면 함수로서 호출됨
      - 이를 객체 안에 `method`에 담아서 호출하면 메서드로서 호출이 됨  
        => 함수 앞의 점(.)이나 대괄호로 구분할 수 있음

    <br>

  - **메서드 표기법**
    ![Alt text](<images/메서드로서 호출.png>)
    - 함수 이름(프로퍼티명) 앞에 객체가 명시된 경우 => 메서드로 호출
    - 그렇지 않은 경우 모두 함수로 호출

#### 2. 메서드 내부에서의 this
- **this에는 호출한 주체에 대한 정보가 담김**
  - 함수를 메서드로서 호출하는 경우 `호출 주체`는 `함수명(프로퍼티명) 앞의 객체`
    - **점 표기법에서 `this`** : 마지막 점 앞 명시된 객체
    - **대괄호 표기법에서 `this`** : 마지막 대괄호 앞 명시된 객체 


### (3) 함수로서 호출할 때 그 함수 내부에서의 this
#### 1. 함수 내부에서의 this
- **함수로서 호출할 경우 this가 지정되지 않음**
  - this에는 호출한 주체에 대한 정보가 담기지만 함수로 호출한 경우 호출 주체(객체지향 언에에서 객체)를 명시하지 않고 개발자가 코드에 관여하여 실행한 것
  - `this가 지정되지 않은 경우 전역 객체를 나타냄`
    - **함수에서의 this는 전역객체를 가르키게 됨**
    - 더글라스 크락포드는 이를 설계상의 오류라고 지적함

<br>

#### 2. 메서드의 내부함수에서의 this
- 위와 같은 오류로 인해 내부함수에서의 `this`가 헷갈릴 수 있음
  - 하지만 단어의 느낌적인 느낌이 아니라 구분법을 통해 구분 가능
    - **함수로서 호출** : 전역 객체
    - **메서드로서 호출** : 호출 주체가 되는 객체를 가르킴

<br>

- 예시 : 내부함수에서의 `this`
    ```js
    var obj1 = {
    outer: function () {
        console.log("outer's this:", this); // (1) obj1

        var innerFunc = function () {
        console.log("innerFunc's this:", this); // (2) window (또는 undefined in strict mode)
        };

        innerFunc();

        var obj2 = {
        innerMethod: innerFunc
        };

        obj2.innerMethod(); // (3) obj2
    }
    };

    obj1.outer();

    ```
    1. obj1 객체를 생성하고 내부 outer 프로퍼티에 익명함수를 연결
    2. obj1.outer를 호출
    3. `obj1.outer 함수`의 `실행 컨텍스트`가 생성되면서 호이스팅, 스코프 체인 정보 수집, this 바인딩 작업 진행
        - outer 함수가 점표기법으로 실행됐기에 메서드로 호출한 것이라 마지막 점 앞 객체인 `obj1이 this에 바인딩`됨
    4. (1) obj1 객체 정보가 출력됨
    5. 호이스팅된 변수 innerFunc는 outer 스코프 내에서만 접근할 수 있는 지역변수로 익명 함수를 할당함
    6. innerFunc를 호출하면서 실행 컨텍스트가 생성되고 호이스팅, 스코프 체인 수집, this 바인딩 등을 수행
        - 함수로서 호출되었기 때문에 this가 지정되지 않고 전역객체 (window)가 바인딩됨
        - (2)에서 window 출력
    7. 호이스팅된 변수 obj2도 outer 스코프 내에서만 접근 가능한 지역 변수로 객체가 할당되며 내부 innerMethod라는 프로퍼티가 함께 할당되며 앞서 정의된 innerFunc과 연결된 익명함수가 연결됨
    8. obj2.innerMethod를 호출하고 실행 컨텍스트가 생성됨
        - 함수명 innerMethod가 점표기법으로 호출되어 메서드로서 호출됨
        - this에 마지막 점 앞의 객체인 obj2가 바인딩됨
        - (3)에서 obj2 객체 정보 출력

    <br>

    - **같은 함수임에도 할당 방식과 호출 방식에 따라 this로 바인딩되는 대상이 달라짐**
      - 실행하는 당시의 주변 환경은 중요하지 않고 오직 해당 함수를 `호출하는 표기법 (점, 대괄호)가 중요함`

#### 3. 메서드의 내부 함수에서의 this를 우회하는 방법
- 내부함수에서 스코프체인에 따라 this를 상속하는 방법은 없지만 **변수를 활용해 우회하는 방법**은 있음

![Alt text](<images/내부함수에서 this를 우회하는 방법.png>)
- innerFunc 내부 this는 전역 객체를 가르킴
- outer 스코프에서 `self` 변수에 `this를 저장`한 상태에서 innerFunc2에서 활용하면 상위 this를 활용할 수 있음
- 일반적으로 상위 스코프의 this를 저장해 내부함수에서 활용할 때 `self`라는 이름으로 식별자 지정

#### 4. this를 바인딩하지 않는 함수
- ES6에서 함수 내부에서 this가 전역객체를 바라보는 문제를 보완하고자 this를 바인딩하지 않는 `화살표 함수`를 도입
- 화살표 함수는 실행 컨텍스트를 생성할 때 `this` 바인딩이 빠지게 되어 상위 스코프의 `this`를 그대로 활용할 수 있음
![Alt text](<images/this를 바인딩하지 않는 함수(화살표 함수).png>)

<br>

- 그 외 call, apply 등의 메서드로 함수 호출 시 명시적으로 this를 지정하는 방법이 있음

### (4) 콜백 함수 호출 시 그 함수 내부에서의 this
- **콜백 함수 : 함수 A의 제어권을 다른 함수나 메서드 B에게 넘겨주는 것**
  - 함수 A는 함수 B의 내부 로직에 따라 실행됨
  - this 역시 함수 B 내부 로직에서 정한 규칙에 따라 값이 결정됨
  - 콜백 함수도 기본적으로 함수이기 때문에 this가 전역객체를 참조
  - `하지만 제어권을 받은 함수에서 콜백 함수에 별도로 this가 될 대상을 지정한 경우 그 대상을 참조하게 됨`

<br>

- 예시 : 콜백 함수 내부에서의 this
![Alt text](<images/콜백 함수 내부에서의 this.png>)
1. setTimeout 함수로 인해 300ms만큼 시간 지연을 한 뒤 콜백 함수 실행 => 0.3초 뒤 전역 객체 출력
    - 콜백 함수를 호출할 때 대상이 될 `this`를 지정하지 않음
2. forEach 메서드는 배열의 각 요소를 차례대로 꺼내어 콜백함수 첫번째 인자로 삼아 함수를 실행 => 전역객체와 배열의 각 요소가 총 5회 출력됨
    - 콜백 함수를 호출할 때 대상이 될 `this`를 지정하지 않음
3. addEventListener는 지정한 HTML 엘리먼트에 `click` 이벤트 발생 시 이벤트 정보를 콜백 함수 첫번째 인자로 삼아 함수를 실행 => `앞서 지정한 엘리먼트와 클릭 이벤트에 관한 정보가 담긴 객체가 출력`
    - 콜백 함수를 호출 시 자신의 this를 상속되도록 정의되어있음
    - 메서드 명의 점(.) 앞부분이 this가 됨

### (5) 생성자 함수 내부에서의 this
- **생성자 함수 : 공통된 성질을 지니는 객체들을 생성하는데 사용하는 함수**
  - **객체지향 언어에서 생성자** : 클래스
    - 클래스 : 공통 속성들을 모아 집합을 정의한 것
      - 예 : 직립 보행, 언어 구사, 도구 사용 등
  - **객체지향 언어에서 객체** : 인스턴스
    - 인스턴스 : 클래스로 정의된 각 개별 객체
      - 공통점도 있지만 저마다 개별 특성이 존재할 수 있음
      - 예 : 인간

## Q&A 

### Q1. 자바스크립트에서 this는 어떤 방식으로 결정되나요?
A1. 자바스크립트에서 `this`는 **함수 선언 시점이 아니라, 호출 시점의 방식에 따라 결정**됩니다.  
함수를 호출할 때 다음과 같은 규칙에 따라 `this`가 바인딩됩니다:

1. **전역 공간에서 호출**: `this`는 전역 객체 (`window`, `global`)
2. **메서드로 호출**: `this`는 점 또는 대괄호 앞에 명시된 **객체**
3. **일반 함수 호출**: `this`는 전역 객체 (strict 모드에서는 `undefined`)
4. **생성자 함수로 호출 (`new`)**: `this`는 새로 생성된 인스턴스 객체
5. **명시적 바인딩 (`call`, `apply`, `bind`)**: `this`는 명시적으로 지정한 값
6. **화살표 함수**: `this`는 자신만의 바인딩을 가지지 않고, **선언된 위치의 외부 스코프의 `this`를 그대로 참조하여 사용합니다.**


---

### Q2. 함수 내부의 this와 메서드 내부의 this는 어떻게 다른가요?
A2. `함수로서 호출`된 함수의 `this`는 전역 객체이며,  
`메서드로서 호출`된 함수의 `this`는 메서드를 호출한 **객체**입니다.

예를 들어:

```js
var obj = {
  method: function () {
    console.log(this);
  }
};

obj.method(); // this는 obj
var fn = obj.method;
fn(); // this는 window (또는 undefined in strict mode)
```

동일한 함수라도 **호출 방식**에 따라 `this`가 달라집니다.

---

### Q3. 내부 함수에서의 this가 전역 객체를 가리키는 이유는?
A3. 내부 함수는 **함수로서 호출**되기 때문에, 호출 주체가 명시되지 않으면 `this`는 **전역 객체**를 가리킵니다.  
비록 내부 함수가 객체의 메서드 안에 정의되어 있더라도, 그 자체가 독립적으로 호출되면 일반 함수로 간주되어 `this`가 전역 객체로 바인딩됩니다.

이를 해결하기 위해 보통 아래와 같은 방법을 사용합니다:

1. `var self = this;` 또는 `const that = this;`로 외부 `this`를 저장하여 내부에서 사용
2. 화살표 함수(ES6)를 사용하여 상위 스코프의 `this`를 그대로 사용

---

### Q4. 화살표 함수에서 this는 어떻게 동작하나요?
A4. 화살표 함수는 **자신만의 this를 가지지 않고**, **자신을 감싸는 외부 스코프의 this**를 그대로 사용합니다.  
이것은 실행 컨텍스트가 생성될 때 **화살표 함수의 this 바인딩이 생략되기 때문**입니다.

예시:

```js
var obj = {
  outer: function () {
    const inner = () => {
      console.log(this);
    };
    inner();
  }
};

obj.outer(); // this는 obj
```

위 예시에서 화살표 함수 `inner`는 외부 함수 `outer`의 `this`를 그대로 참조합니다.

---

### Q5. 전역 변수와 전역 객체의 관계, 그리고 delete 연산자의 작동 방식은?
A5. 자바스크립트에서 전역 변수와 전역 객체는 비슷해 보이지만, 실제로는 다르게 동작합니다.

먼저 var로 전역에서 선언한 변수는 전역 객체의 프로퍼티처럼 동작합니다. 예를 들어 var a = 1이라고 선언하면, window.a 또는 this.a로도 접근할 수 있습니다. 하지만 이 변수는 삭제할 수 없습니다. 자바스크립트 엔진이 내부적으로 이 프로퍼티를 [[Configurable]]: false로 설정하기 때문입니다. 즉, 전역 객체의 프로퍼티처럼 보이지만 보호되어 있어서 delete 연산자로 삭제할 수 없습니다.

반면에 let이나 const로 선언한 전역 변수는 아예 전역 객체의 프로퍼티로 등록되지 않습니다. 즉, let a = 1이라고 선언해도 window.a는 undefined이며, 전역 객체를 통해 접근하거나 삭제하는 것이 불가능합니다.

만약 전역 객체에 직접 프로퍼티를 추가하는 경우, 예를 들어 window.b = 2처럼 할당하면, 이건 일반 객체의 프로퍼티와 같기 때문에 delete window.b를 통해 삭제할 수 있습니다.

정리하자면,
- var 전역 변수: 전역 객체에 등록되지만 삭제는 불가
- let / const 전역 변수: 전역 객체에 등록되지도 않음, 삭제도 불가
- 전역 객체에 직접 할당: 등록되고 삭제도 가능
